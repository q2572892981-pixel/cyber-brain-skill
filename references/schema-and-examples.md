# Schema and examples

## Evidence layers

Every meaningful memory should be traceable through three separate layers:

```yaml
证据:
  原始证据: "用户原话或准确来源定位"
  提取事实/明确观点: "从原话直接得到的事实或观点"
  AI推断: "模型根据多个事实做出的推测；不能冒充用户观点"
```

If the original source is too long, store a short faithful excerpt plus a date, speaker, section, or source label. Do not invent line numbers or quote wording the user did not say.

## Lifecycle and strength

```yaml
元数据:
  生命周期: 新增|强化|修正|失效|归档
  记忆强度: 临时|普通|核心
  变化时间: "YYYY-MM-DD or null"
  变化原因: "用户确认、重复出现、事实变化、被新证据修正等"
  关联旧记忆: ["CB-..."]
```

`临时` is for an unconfirmed or context-bound signal. `普通` is supported and useful but not yet central. `核心` requires repeated evidence or explicit confirmation. Strength must never increase merely because the model finds an idea persuasive.

## 判断什么值得记

优先级从高到低：

1. 用户明确做出的重要决定、承诺或行动；
2. 改变了原判断的新发现；
3. 稳定的偏好、价值判断、工作方式；
4. 反复出现且会影响未来建议的模式；
5. 重要人物、项目、关系和上下文；
6. 尚未解决但值得未来验证的问题。

不长期记忆：寒暄、口头禅、单纯情绪宣泄、没有后续意义的细节、同一句话的重复表达。

如果内容涉及健康、财务、身份、联系方式、家庭矛盾或其他敏感信息，默认只在当前回答中使用，不写入长期记忆；除非用户明确要求保存。

## 不丢语义的清理规则

- “可能、我猜、暂时、但是、其实、我不确定”等限定词不能删掉。
- 否定词、比较词、时间词、数量、人物关系和因果词不能删掉。
- 口语很乱但表达了观点时，改写句子，不改观点强度。
- 同一观点多次出现时合并，并保留后一次的修正。

## 示例输入

```text
今天先不聊工作啊，那个，我最近其实一直在想，之前我觉得做内容最重要的是多发，发得越多越容易涨粉。但是这两天我发现不是这样，我有一条视频播放量明显高一点，原因可能不是数量，而是它把我自己踩过的坑说得比较具体。所以我想先别一天发五条了，接下来一周每天最多一条，先看看什么因素真的有效。这个还没验证，我也不知道是不是偶然。
```

## 冲突处理

如果旧记忆是“我认为应该每天高频发布”，新内容是“我决定一周每天最多一条”，输出：

```yaml
冲突:
  旧记忆: "高频发布优先"
  新记忆: "先控制频率，验证内容因素"
  判断: "明确的观点变化"
  建议状态: "旧记忆标记 superseded，新记忆标记 active"
```

如果只是语气变化或上下文不同，不要判定冲突，标记为 `可能重复/冲突` 并提出一个确认问题。

## Challenge example

用户说：“我准备重新每天发五条，先把量堆起来。”

```yaml
当前判断: "通过提高发布量快速做大账号"
支持证据:
  - "用户过去曾认为高频发布有助于增长"
反对证据:
  - "最近一次复盘中，用户明确决定控制频率，先验证具体内容因素"
与历史的相似之处:
  - "都在缺少验证时，试图用增加数量解决增长问题"
可能忽略的信息:
  - "当前高表现视频的原因尚未验证，增加数量可能冲淡信号"
Cyber Brain 的最终判断: "不建议现在直接恢复每天五条；先做一周小规模验证。"
置信度: medium
引用的历史记忆: ["CB-20261028-001"]
```

## 更新记录

当已有记忆被新材料修正时，不要创建第二张几乎一样的卡片。保留原 ID，并记录：

```yaml
更新记录:
  - 时间: "2026-10-30"
    变化: "从高频发布改为先控制频率验证内容因素"
    依据: "用户新陈述"
```
